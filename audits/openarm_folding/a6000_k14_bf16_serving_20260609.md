## PI0.5 Dtype Pattern

Inspected `src/lerobot/policies/pi05/modeling_pi05.py`:

- `Pi05Policy` constructs `PaliGemmaWithExpertModel(..., precision=config.dtype, ...)`.
- `PaliGemmaWithExpertModel.to_bfloat16_for_selected_params("bfloat16")` casts the model to bf16, then keeps these paths in fp32:
  - `vision_tower`
  - `multi_modal_projector`
  - `input_layernorm`
  - `post_attention_layernorm`
  - `model.norm`
- `_preprocess_images` forces image tensors to `torch.float32`.

K14 keeps that mixed precision pattern. Preprocessor and postprocessor objects are not cast by K14, so normalizer/stat handling remains on the existing path.

## Code Change

Changed only `src/lerobot/async_inference/policy_server.py`.

Added:

- `_configure_serving_precision()`
  - reads `self.policy.config.dtype`
  - enables `self._serving_autocast_dtype = torch.bfloat16` only when `config.dtype == "bfloat16"` and the policy device is CUDA
  - reapplies PI0.5 `to_bfloat16_for_selected_params("bfloat16")` when available, preserving the model's selected fp32 paths
  - logs policy parameter dtype counts
- `_serving_autocast_context()`
  - returns `torch.autocast(device_type="cuda", dtype=torch.bfloat16)` when enabled
  - returns `nullcontext()` otherwise
- `_predict_policy_action_chunk()`
  - wraps every `policy.predict_action_chunk(...)` call in the configured serving autocast context

Call sites now use `_predict_policy_action_chunk(...)` for:

- K8a no-prefix warmup
- K8a guided RTC warmup
- RTC guided action chunk inference
- non-RTC action chunk inference

Policy load order:

```text
from_pretrained(...)
policy.to(device)
_configure_serving_precision()
_configure_rtc_policy()
make_pre_post_processors(...)
warmup
```

## Conclusion

K14 is safe to keep:

- training/config dtype is already `bfloat16`
- PI0.5 mixed fp32 paths are preserved
- action sanity shows small numerical difference
- server remains live on `8081`
- measured forward improvement is real but modest

K14 does not fully solve the forward bottleneck. The next larger levers are:

- torch compile with explicit compile-warmup budget and cold-start handling
- model-side denoising/guidance cost reduction
- postprocess vectorization only as a small `5-7 ms` cleanup
