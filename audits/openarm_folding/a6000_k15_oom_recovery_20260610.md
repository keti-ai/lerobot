## Mitigation Choice

Chosen mitigation: **(c) disable torch.compile and run the K14 bf16 fallback by default**.

Reason:

- The K15 compiled server accumulated CUDA memory from the startup baseline to 43.5 GiB across live D07f/i/j usage.
- K15 synthetic validation used fixed request shapes and showed no recompile, but live RTC requests vary `inference_delay` and leftover prefix lengths.
- Re-running compile-on live-like stress on the shared server risks reproducing the OOM while live eval is waiting.
- K14 bf16 fallback already measured around the 0.4 s server forward range and is inside the 1 s chunk window.
- Stability is higher value than the K15 `~100 ms` synthetic speedup for this live recovery.

Code change:

- `src/lerobot/async_inference/policy_server.py`
- torch.compile serving is now opt-in via `LEROBOT_ASYNC_SERVER_TORCH_COMPILE=1`.
- Default server behavior is no-compile, keeping:
  - K14 bf16 autocast
  - RTC horizon 10
  - K8a warmup discard
  - K13 timing logs

This avoids growing the Dynamo/Inductor graph cache on live shape variation. `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` is also used in the recovery launch to reduce allocator fragmentation, but the primary mitigation is compile-off.
